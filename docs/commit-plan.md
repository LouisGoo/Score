# 打分系统逐次提交计划

需求基线：[产品需求与架构设计 V1.1](在线打分系统-产品需求与架构设计.md)。
技术栈：React + Vite + TypeScript、FastAPI、MySQL InnoDB、Redis。
当前交付目标为通用版 P0；单位短号、人员库、SSO 与多阶段比赛留在 P1。
前端批次（14a～17）的接口对应、基础约定与后端缺口评估见 [前端开发计划](frontend-plan.md)。

## 协作与 review 节奏

1. 每次选取下表中的一个提交单元，先说明范围，再实现、验证、自查。
2. 提交单元完成后，交付文件入口、验证命令/结果、review 重点及建议 commit message。
3. 默认先保留未提交变更，交由用户 review；按用户后续要求修订或提交。未经要求不 push。
4. 当前批次 review 后再推进下一批，避免累积难以审查的大改动。
5. 每个提交应可独立通过已有检查；涉及业务写入时，权限、事务和审计与业务实现同时交付。
6. 复杂单元可在开工前拆成 a/b 两个提交；同步更新此表，不把未完成范围标为完成。
7. 以下为实施顺序，默认依赖前序已完成提交。数据库迁移随相关功能新增，不一次性建立所有未来表。

8. 每个接口变更随同一 commit 更新 [接口文档](api.md) 的实现状态、权限、错误与重试约定；字段结构以代码生成的 OpenAPI 为准。
