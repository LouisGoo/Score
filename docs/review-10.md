## 自查结论

1. 身份由服务端会话指定；Origin/CSRF、会话有效期、凭证版本、活动绑定及冻结应交资格均校验。写事务重新验证 principal；任务锁等待后再次检查会话到期。跨活动 404，主办方不能代填，其他评委无法读取回执。
2. 活动 → 评委/会话 → 任务的锁顺序与凭证重置/退出/控制兼容，READ COMMITTED。截止严格使用锁内时间，`now == deadline` 拒绝；暂停及旧任务新提交拒绝，不限时按 null 处理。
3. UUID 按评委唯一，摘要包含任务和完整请求。维度顺序、等值十进制文本规范化；相同 key 同内容复用原回执，不同内容 409。回执核验位于新写入状态/截止校验之前，仍要求当前身份和资格有效。改分后旧 key 仍返回原版本，GET 无 key 返回最新版本。
4. 评分核心校验全量维度、重复维度、范围、步长和规则版本；零分有效、空值/float/NaN 不合法。原始分完整保存为 JSON 十进制字符串，个人计算缓存 DECIMAL(65,30)，展示分由核心结果直接 ROUND_HALF_UP 后保存 DECIMAL(5,2)。后续结果只能基于原始分和规则复算，避免个人总分提前舍入影响汇总。
5. 当前版本、历史、回执、审计、活动版本及 outbox 同事务；改分不新增逻辑评分单。审计记录前后 revision 和 request_id，不重复复制原始分或秘密；outbox 只有内部标识和进度元数据，不直接广播。
6. 仅 MySQL 1205/1213 进行完整事务重试，最多 3 次；退出事务释放连接后随机短退避，再重查权限和截止，沿用原 key。连接异常/提交结果不明返回 503，调用方通过原 key 或本人回执核验。没有无限等待或自动换 key。
7. HTTP 成功只在提交之后返回；提交后响应丢失、应用实例重建、审计/outbox 写入失败和改分回滚均有专项验证。幂等记录与历史不自动清理。
