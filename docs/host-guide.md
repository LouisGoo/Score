# 主持人活动操作手册

## 活动开始前

1. 与维护者确认最近备份可恢复、服务可用、数据库有余量。用当天实际手机/网络做一轮试评。
2. 登录主办方，创建活动草稿，填写活动名称、评分对象、评委、规则、最低有效份数和时限。编号按字符串处理，注意前导零。
3. 确认算法、去极值条件、维度权重和步长。先核对人员及对象顺序，再发布；发布后名单和规则冻结，配置错误应新建/复制活动修正。
4. 私下分发评委身份码或私人邀请链接，核对评委身份。公共二维码仅用于加入，不包含私人身份码。
5. 提前创建大屏授权，在投影设备打开大屏并全屏，核对公共二维码、主题和当前活动。不要投影管理页或私人邀请页。

## 评分过程中

1. 确认所有评委进入正确活动，再对当前对象“开评”。同一活动不能同时开两个任务。
2. 看已交人数和评委状态；主持人不能代填分。让评委等到成功回执再离开页面，分数为 0 与未填不同。
3. 需要临时中断时先暂停，再解释原因；恢复后继续。限时任务按系统显示的剩余时间执行，不以主持人口头时间为准。
4. 评委提交超时：先查看本人回执或按页面核验，不反复新建提交。重新联网不会自动补交断网时的旧草稿。
5. 收齐后收评；未收齐提前收评或跳过时说明原因，保留审计。网络断开后先刷新确认实际状态，不重复盲点按钮。
6. 检查有效份数、缺交、原始分、剔除标记及最终分。低于门槛不能公布有效成绩；未公布时可按实际情况重开补评并填写原因，也可按业务规则标记无结果。
7. 核对无误后公布；公布后的冻结成绩不能靠重开直接更改。大屏只显示已公布成绩。进入下一个对象前确认当前任务已处理。

## 常见情况

| 情况 | 主持人处理 |
| --- | --- |
| 提示版本冲突 | 刷新状态后决定下一步，不凭旧页面重复提交 |
| 评委换手机或身份码泄露 | 由主办方填写原因重置凭证/会话，私下交付新码；旧凭证/会话失效 |
| Redis/实时连接故障 | 查看页面同步提示，等待轮询恢复；以回执和服务端状态为准 |
| 数据库不可用或提交失败 | 暂停活动，联系维护者；没有回执不算成功，不要求评委不停重试 |
| 评委本地草稿丢失 | 未提交草稿不保证可恢复；重新核对对象和剩余时间再输入 |
| 大屏链接外泄 | 撤销旧授权并创建新授权，重新打开展示设备 |
| 已公布结果有争议 | 保存导出和审计，联系负责人；不要直接改数据库或覆盖已公布记录 |

## 活动结束后

1. 确认所有对象已处理；系统指出未完成任务时先处理，再结束活动。
2. 导出成绩汇总、明细和审计。默认只导出已公布成绩；包含未公布时须显式选择并注意标记。
3. 核对导出对象数、名次、并列和最终分，再归档。归档不会删除评分，也不会释放数据库空间。
4. 通知维护者执行活动后备份并检查容量，按约定权限保存导出。
5. 记录活动负责人、时间、异常及处理原因，敏感凭证不放进普通聊天群或操作记录。

## 报障时提供

活动名称、出错时间、操作步骤、错误提示和请求编号（页面可获得时）。截图遮挡身份码、邀请链接、患者信息；不要提供密码、Cookie、令牌或数据库连接串。
