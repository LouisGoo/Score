# Review 08：评委会话兑换、重置与撤销

日期：2026-10-12。基于 07 的 1603bcd；按用户授权自行验收并提交，不 push。

## 交付范围

- judge_sessions/router.py、schemas.py、dependencies.py、service.py：公开活动预览、独立 bootstrap CSRF、身份码验证、用户确认后兑换会话、本人会话查询、主动退出。
- models.py 与 0008_judge_sessions：确认令牌、评委会话、评委认证审计三张 InnoDB 表。令牌仅存 SHA-256，确认绑定浏览器/活动/评委/凭证版本，180 秒一次性使用；会话默认绝对有效期 24 小时。
- credentials/service.py：READY/RUNNING 的有原因重置，禁止当前码及他人码；版本递增、旧会话及未消费确认令牌撤销、原因审计同事务，不改变评委 ID/冻结名单。
- 共享 MySQL 限流复用主办方计数机制但独立命名空间，按来源、活动及码尝试组合控制；默认来源容量允许多评委共用 IP，不宣称已完成容量测试。

## 自查重点

1. 所有写请求有 Origin/CSRF；主办方/评委 Cookie 与会话 CSRF 分离。verify 不建立会话，客户端不能提供 judge_id；仅本人身份信息供确认，公共预览无名单/成绩/凭证。
2. 慢哈希在连接和行锁之外执行，随后活动 → 评委顺序加锁重新检查状态与凭证版本。兑换再锁确认令牌和会话，锁内读取当前时间，阻止过期、已消费、重置及跨浏览器确认。
3. 数据库生成列 active_judge_id + 唯一约束独立阻止两条未撤销会话。过期会话在兑换时先撤销并 flush；相同浏览器重新确认复用原会话且不续期；第二台设备被拒绝，换机要重置。
4. 每次鉴权从数据库联查会话有效期/撤销/凭证版本。写事务用 lock_principal 再检查，防止依赖层鉴权后发生重置；刷新 ORM 已缓存的记录，避免锁后使用旧值。后续评分写事务仍需同时落实活动和任务状态/截止限制。
5. 重置同时更新凭证、会话和确认令牌，活动版本递增，审计失败全部回滚。审计仅含版本、来源、时间、原因和内部 ID；无身份码/验证哈希/HMAC/会话令牌。
6. 结束/归档后 verify/exchange/reset 均拒绝；已有有效会话可只读查询本人身份。退出不受活动只读限制。真正结束操作在 11、成绩读接口在后续、实时撤销通知在 18。
7. 无自动幂等重试；确认响应丢失可重做 verify，兑换响应丢失先 GET me，未收到 Cookie 的已建会话须重置恢复，不允许抢占。重置响应丢失只能核验版本并重新生成，不能恢复明文。
