# Review 24：备份恢复与活动操作手册

## 实现

- `backend/src/score_api/ops.py`：backup / restore / fingerprint / storage 四个显式 CLI 子命令，不读取应用 .env，不提供删除命令或自动调度。
- MySQL 8 单事务逻辑备份，仅项目 score_ InnoDB 表；gzip + SHA-256 清单，拒绝覆盖已有输出，失败清理自身 partial 文件，600 权限临时客户端配置与备份文件。
- 恢复只接受独立、已创建、空的 *_restore 数据库和精确确认参数；先验证摘要与 gzip，再导入，检查表集合。失败不假装回滚 DDL，不自动覆盖、删库或切换应用。
- 一致性读下逐表主键排序哈希与行数核对，包含全部改分历史、永久幂等回执、冻结结果、审计与 outbox。
- 容量检查包含当前库所有表的数据及索引估计值；350/425 十进制 MB 对应 warning/10、critical/20，失败/1，正常/0；阈值可配置。无监控平台或告警推送。
- [备份恢复及保留策略](backup-recovery.md)、[主持人操作手册](host-guide.md)、[上线检查单](go-live-checklist.md)。
- CI backend 新增第二个独立 MySQL 服务、MySQL 客户端与恢复测试环境；配置语法检查通过，未推送执行远端 CI。
- 备份文件排除 Git/Docker 构建上下文；生产需求说明同步为基础日志范围。

2. 独立实例恢复集成测试：本地原有 MySQL 8.0 测试服务作为源；新建独立数据目录及端口的 MySQL **8.0.46** 作为目标；客户端为 **8.0.46**。源/目标测试数据库由本次随机创建，测试后删除，目标进程停止。未连接远端/正式数据库。
3. 测试通过真实 API 创建两评委活动，保存零分、改为 100 分、另一评委 80 分，收评并公布；备份、异实例恢复后全部项目表行数/摘要一致。

5. 重复导入非空目标被拒绝，拒绝后摘要不变；客户端不存在时备份失败，不留下成功文件或 partial。storage 对真实测试库返回正数。

演练中的服务初始化、工具安装和测试前置不计为恢复耗时；pytest 总耗时包含 API 数据准备及清理，不能作为正式 RTO。小型本地样本不代表 500MB 或正式服务器的速度。

## AT-28 与边界

AT-28 已具备本地证据：阈值边界自动化测试、真实数据库容量查询、独立 MySQL 实例逻辑恢复、逐表核对、回执重放及结果复算。没有为触发阈值制造数百 MB 正式数据，也未验证托管服务控制台计量、备份权限、远程 TLS 或正式数据规模恢复耗时。

工具假设所有项目业务表使用 score_ 前缀、InnoDB 且无自定义触发器；备份期间禁止 DDL。SHA-256 发现损坏，不代替签名/可信来源。SQL 只能恢复自己的可信备份，账号只授予目标库权限。恢复失败可能留下部分目标数据，必须先检查再另建空库重试。

350/425MB 来自原 500MB 配额假设，实际购买数据库后需重新确认。没有自动清理；已投递 outbox、过期会话的建议候选条件在手册中，未投递事件、有效会话、评分/幂等记录/全部审计不随意删除。180 天不是自动删除期限。

编号 23 未执行，不宣称 50 评委容量或 P95 达标。正式使用前仍须完成目标环境上线检查、受控备份副本、实际权限/证书验证和至少一次实际环境恢复演练。
