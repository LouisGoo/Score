# 16：评委手机评分流程

日期：2026-10-14。状态：开发完成，保留未提交变更供 review。

## 交付

- `/join`：手输活动码；`/join/:publicCode`：公共二维码落地、活动预览、身份码验证、姓名与编号确认、会话兑换。
- 私人邀请读取 `#code=` 后立即清除地址栏，仅自动验证，必须由本人确认后才兑换；兑换响应丢失时经 `/me` 恢复，不自动重新兑换。
- `/judge/events/:eventId`：恢复身份、等待开评、评分/暂停/截止、提交前核对、回执和开放期改分。
- `/judge/events/:eventId/history`：本人最新评分、此前版本回执、已公布对象成绩。使用评委快照，不读取管理快照或其他评委原始分。
- 活动结束后只读。退出及运行中身份失效清理对应评委的草稿、待核验记录和查询缓存。
- 未改后端接口、数据库结构、依赖锁文件；无需迁移。

## 手机布局评估与实现

采用弹性单列布局。评分是一条按顺序阅读和输入的任务流，固定宽高或按屏幕比例整体缩放会使短屏按钮被遮挡、宽屏文字过度拉伸，因此不设置固定画布或长宽比。

- 容器 `width: 100%`、`max-width: 640px`；手机占满可用宽度，平板与电脑居中，保持适合阅读的行宽。
- 页面使用纵向 Flex，导航/按钮组允许换行；输入行两侧加减按钮固定 44px，中间输入框弹性伸缩并允许收缩。
- `100vh` 回退加 `100dvh` 最小高度；内容自然撑高，可纵向滚动。提交区留在正常文档流内，避免固定底栏在软键盘和横屏短屏时覆盖输入。
- `viewport-fit=cover` 与四边 `safe-area-inset-*` 留白；长标题、编号、回执、错误请求编号允许换行。
- 普通输入字号至少 16px，分数 22px；主要输入、按钮、导航触控高度至少 44px。确认弹窗宽度不超过视口减 24px，短屏可滚动。
- 手机样式单独随 judge 模块加载；未引入管理端页面组件。

## 提交正确性

1. 初始值为空，不预填零或满分；零分有效。分数保持字符串，使用已有十进制工具校验范围/步长，显示个人百分制总分；90、8、18 示例为 87.00。
2. 草稿按活动、评委、任务、规则版本隔离。对象切换时重新挂载评分表单，关闭旧对象确认弹窗，保留旧草稿并提示；旧分数不会流入新对象。
3. 打开提交确认前主动同步快照，核对对象版本、本人评分版本、规则版本和截止状态；弹窗显示对象、各维度分、总分及将产生的版本。后台状态变化后禁用旧确认。
4. 确认时生成 UUID，将原 key 与完整请求体持久化后才发送 PUT；同步锁防止双击。浏览器拒绝存储时明确拦截提交，避免发送后无法恢复核验。
5. 超时、断网、5xx 保留原请求，按原 key GET 核验，不凭其他版本的回执推断成功。刷新页面或切换对象后仍可核验旧对象；核验未找到不会自动重发。
6. 用户选择“使用原提交重试”时先同步快照，再重用原 key 和请求体。服务端明确拒绝后保留草稿、刷新状态；不确定结果继续保留待核验记录。收到 `Retry-After` 时等待，不立刻核验或重发。
7. 开放期允许改分才显示修改入口，发送已有 revision；冲突后刷新，不能覆盖新版本。回执展示服务端编号、接收时间、规则版本、评分版本和总分。
8. 跨标签切换身份时，快照身份不符会要求重新加入；CSRF 刷新发现身份变化时禁止自动重放原评分。确认时如已有另一页面的待核验记录，先核验，不覆盖其原 key。

快照采用 5 秒 ±20% 抖动轮询；后台暂停，回到前台/重连刷新，写操作后刷新，结束/归档后停止定时轮询。倒计时以 `server_time` 修正本地时钟，暂停显示冻结的剩余时间。断网恢复不自动补交草稿。
